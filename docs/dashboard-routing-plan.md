Source requirements: `docs/preishare-dashboard-requirements.md` (sections 2–4: investor
goals, primary screens, and layout regions). Related: `docs/dashboard-ia.md`.

## Planned dashboard route tree

```text
/                          → landing page (exists)
/dashboard                 → layout route (shell: header + sidebar + outlet)
/dashboard                 → index (investor home: metrics, portfolio summary, activity)
/dashboard/portfolio       → child page (holdings table; exists)
/dashboard/deals           → child page (open deals; exists)
/dashboard/profile         → child page (read-only profile; exists)
/dashboard/activity        → placeholder child (future full activity feed; not created yet)
```

## Layout vs page responsibilities
- **Layout (`route.tsx`, today `dashboard.tsx`)**: persistent chrome only: header, sidebar /
  mobile menu, and the main `<Outlet />`. No metric cards or page content.
- **Index (`index.tsx`)**: dashboard home composition (stats cards, portfolio summary,
  recent activity). Renders inside the parent layout.
- **Child pages and placeholders**: one area each, rendered inside the same layout so the
  shell never reloads. Placeholders stay minimal until a later sprint.

## Out of scope for this plan
- Component prop designs and styling (already covered by `docs/component-plan.md`)
- Auth guards, sign-in pages, and loader data shapes (later sprint)
- API routes, Supabase/PostgreSQL queries, and pgvector search
- Deleting or renaming existing routes other than the planned `dashboard.tsx` → `dashboard/route.tsx` move
- Removing the starter `/about` page and starter header/footer (separate cleanup task)

## Success criteria for implementation steps
- Visiting `/dashboard` shows the layout shell and the home index content.
- `/dashboard/portfolio`, `/dashboard/deals`, `/dashboard/profile` (and later `/dashboard/activity`)
  render inside the same layout, not as a full-page replacement of the shell.
- After the layout move, there is exactly one `/dashboard` layout file and every URL still works.
- No unrelated existing routes are deleted during dashboard work.
